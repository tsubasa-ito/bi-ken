# PRD — 美術検定（BiKen）

**バージョン:** 1.0  
**作成日:** 2026-05-11  
**オーナー:** tsubasa-ito

---

## 1. 概要

### プロダクトビジョン
「美術検定の合格を、スマホで毎日5分から」

美術検定4級テキスト掲載の名作100点を教材として、作品と作家名を結びつける4択クイズを通じて美術知識を体系的に身につけるための iOS 学習アプリ。

### ターゲットユーザー
- 美術検定4級の取得を目指す学習者（10代〜40代）
- 美術・芸術に興味があり、名作を体系的に学びたい人
- 隙間時間を有効活用したい社会人・学生

### プラットフォーム
- iOS 17.0 以上
- iPhone（Portrait 固定）

---

## 2. 背景と課題

### 課題
- 美術検定の参考書はテキストベースで、視覚的に作品と作家名を結びつける学習手段が少ない
- 名作を「見て覚える」体験をスマホで手軽に行えるアプリが存在しない
- 継続的な学習習慣を作りやすい仕組みが必要

### 解決アプローチ
- テキスト掲載の名作100点を Wikipedia API から実際の作品画像とともに出題
- ゲーミフィケーション（XP・レベル・ストリーク）で継続学習を促進
- 毎日リマインダーと学習進捗の可視化で習慣化をサポート

---

## 3. 機能要件

### 3.1 作品データ

#### F-01: 名作100点の提供
- `TextbookArtworkData.all` に美術検定テキスト掲載の名作100点をハードコード
- 各作品は以下の情報を保持する
  - 作品名（日本語・英語）
  - 作家名（日本語・英語・原語）
  - 制作年（任意）
  - 技法・素材
  - 時代区分（Era enum）
  - 説明文・作家略歴

#### F-02: 作品画像の取得
- Wikipedia Action API（`prop=pageimages&redirects=1`）で作品画像を非同期取得
- `wikiTitle` が設定されている作品のみ画像を取得し、取得できない場合はプレースホルダーを表示
- URLCache（メモリ 50MB・ディスク 200MB）でセッション中の重複リクエストを防止
- 恒久的失敗（記事なし・サムネイルなし）のみキャッシュし、ネットワークエラーは再試行可能にする

### 3.2 クイズ機能

#### F-03: クイズモード
以下の5モードを提供する。

| モード | 内容 | 出題数 |
|---|---|---|
| `random(Int)` | 全作品からランダム出題 | 5 / 10 / 20 / 全問 |
| `era(Era)` | 時代別（ルネサンス・バロック・印象派など）でランダム出題 | 最大10問 |
| `review` | 過去に間違えた作品からランダム出題 | 最大20問 |
| `specificIDs` | 結果画面で選択した間違い問題のみ復習 | 選択数 |
| `bookmark` | ブックマーク登録した作品から出題 | ブックマーク数 |

#### F-04: 4択クイズ形式
- 問題：作品画像（または作品名プレースホルダー）を表示し「この作品の作者は？」と問う
- 選択肢：正解1択＋同一時代の作家から誤答3択を自動生成
- `precondition` で選択肢に正解が含まれることを保証
- ヒント：制作年代・技法を表示

#### F-05: 回答フィードバック
- 回答直後に選択肢の色を変更（正解：緑、不正解：赤）
- 正解の選択肢を常にハイライト
- 解説パネルで作品情報・作家名・検定ポイントを表示
- ブックマークボタンを解説パネル内に配置

#### F-06: クイズ結果画面
- 正答数・正答率を大きく表示
- 全問の正解・不正解一覧をスクロール表示
- アクション：「間違えた問題を復習」「もう一度（同じモード）」「ホームへ」

### 3.3 進捗・ゲーミフィケーション

#### F-07: XP・レベルシステム
- 正解1問につき XP を加算（難易度による加算値の差は現バージョンでは未実装）
- XP が100に達すると自動レベルアップし `totalCertificates` が加算される
- 現XP（`currentXP`）は0〜99の範囲で保持（レベルアップで0リセット）
- レベルに応じた称号を表示

| レベル | 称号 |
|---|---|
| 1 | 入門者 |
| 2 | 絵の卵 |
| 3 | 絵描き志望 |
| 4 | 画学生 |
| 5 | 見習い学芸員 |
| 6 | 学芸員 |
| 7以上 | 美術鑑定士 |

#### F-08: 連続学習ストリーク
- 学習した日付を ISO8601 形式で最大28件記録（`studyDateStrings`）
- 連続学習日数（`currentStreak`）をホーム画面に表示
- クイズ進行中のトップバーにも連続正解数（streakChip）を表示

#### F-09: 日次目標
- 1日の目標問題数（`dailyGoal`、デフォルト10問）を設定可能
- 当日回答済み問題数（`todayArtworksMet`）を日付変更時に自動リセット
- ホーム画面で当日の進捗を確認できる

#### F-10: 間違え記録・ブックマーク
- 不正解の作品は `wrongArtworkIDs` に記録（重複なし）
- ブックマーク登録・解除は `toggleBookmark()` で操作
- 進捗リセット（`reset()`）でこれらを含む全データを初期化

### 3.4 ホーム画面

#### F-11: デイリー作品カード
- 日付シードで毎日1点の作品を固定表示
- 作品画像を1件フェッチして作品名・作家名とともに表示
- タップで `ArtworkDetailView` へ遷移

#### F-12: スタッツ表示
- 正答率・連続正解数・挑戦回数をカード形式でホーム画面に常時表示

### 3.5 作品詳細

#### F-13: ArtworkDetailView
- 作品画像・タイトル・作家名・制作年・技法・時代タグを表示
- 説明文・作家略歴を読める
- 右上のブックマークボタンでブックマーク登録・解除

### 3.6 設定

#### F-14: 通知・リマインダー
- プッシュ通知の許可リクエスト・ステータス表示
- 毎日リマインダーのオン/オフと時刻を設定（`UNCalendarNotificationTrigger`）
- アプリがフォアグラウンドに戻ったとき通知状態を再取得

#### F-15: 進捗リセット
- `confirmationDialog` による二段階確認でデータを全リセット

#### F-16: アプリ情報・ヘルプ
- バージョン情報・機能紹介（AboutView）
- FAQ アコーディオン（HelpView）
- ストアレビューリクエスト（`@Environment(\.requestReview)`）

### 3.7 広告

#### F-17: バナー広告
- ホーム画面下部に AdMob バナーを固定表示（safeArea 内）

#### F-18: インタースティシャル広告
- クイズ終了後（結果画面表示前）に全画面広告を表示
- 広告が準備できていない場合は即スキップ
- 表示後に次の広告をプリロード

### 3.8 アプリアップデート通知

#### F-19: アップデートアラート
- iTunes Search API でストア最新バージョンを1日1回チェック
- 新バージョンが存在する場合、App Store へのリンクを表示
- API 呼び出し成功後のみ「最終チェック日」を更新（失敗時のスキップを防止）

## 4. 非機能要件

### 4.1 パフォーマンス
- URLCache（メモリ 50MB・ディスク 200MB）で画像の再取得を抑制
- `withTaskGroup` でクイズ用画像を並列フェッチ（一問ずつの逐次フェッチを禁止）
- actor 再入バグを防ぐため、`inFlight` タスク辞書で同一 wikiTitle の重複リクエストを防止

### 4.2 オフライン対応
- 作品データ（名前・情報）はローカルに保持するため、ネットワーク不要
- 画像取得失敗時はプレースホルダーを表示し、クイズは正常に続行できる

### 4.3 プライバシー・セキュリティ
- 個人情報の収集なし（ユーザー名は任意入力、ローカル保存のみ）
- 学習進捗データはすべて `UserDefaults` にローカル保存（クラウド同期なし）
- Firebase Crashlytics によるクラッシュレポート収集（`GoogleService-Info.plist` が存在する場合のみ）

### 4.4 クラッシュ監視
- Firebase Crashlytics でクラッシュを収集・分析
- `GoogleService-Info.plist` が不在の場合もアプリはクラッシュしない

### 4.5 Swift 6 / Concurrency
- `@Observable` + `@MainActor` ViewModel
- ObjC delegate（AdMob 等）は `nonisolated func` + `Task { @MainActor [weak self] }` パターン
- `actor` で非同期サービスを保護（WikipediaImageService・AppUpdateService）

## 6. データモデル概要

```
TextbookArtwork          作品の教材データ（ローカル静的）
    └─ asArtwork()  →  Artwork      表示・クイズ用モデル
                            └─ QuizQuestion    4択問題

UserProgress（singleton）
    ├─ level / currentXP / totalCertificates
    ├─ currentStreak / studyDateStrings
    ├─ wrongArtworkIDs
    ├─ bookmarkedArtworkIDs
    └─ dailyGoal / todayArtworksMet
```
